블로그를 만들 때 가장 먼저 정한 것은 편집기가 아니라 글이 어디에 남을지였다. 지금은 별도 CMS 대신 저장소 안의 MDX 파일을 원본으로 사용한다.

## 지금 필요한 만큼만

아직 글이 많지 않고 작성자도 한 명이다. 인증, 데이터베이스, 관리자 화면을 먼저 만드는 것은 블로그보다 블로그 시스템을 만드는 일에 가까워질 수 있다.

MDX를 선택하면 Markdown의 읽기 쉬운 문법을 유지하면서 필요할 때 React 컴포넌트를 글 안에 넣을 수 있다. 글 변경 이력도 코드와 같은 방식으로 남는다.

```tsx
export const metadata = {
  title: "글 제목",
  date: "2026-06-26",
  tags: ["Next.js", "MDX"],
}
```

각 글은 제목, 설명, 날짜, 태그, 예상 읽기 시간을 내보낸다. 목록과 상세 페이지는 이 정보를 함께 사용하므로 같은 내용을 여러 곳에 적지 않는다.

## 나중에 바꿀 수 있는 것

글이 쌓이면 전문 검색과 태그별 모아보기가 필요해질 수 있다. 여러 사람이 작성하게 된다면 CMS가 더 편할 수도 있다.

지금의 선택은 CMS를 영원히 쓰지 않겠다는 뜻이 아니다. 현재 규모에서 글을 가장 빨리 쓰고 오래 보관할 수 있는 방법을 고른 것이다.

## 참고한 자료

처음부터 모든 규칙을 직접 만든 것은 아니다. MDX 설정과 동적 글 경로의 정적 생성 방식은 [Next.js 공식 MDX 가이드](https://nextjs.org/docs/app/guides/mdx)와 [generateStaticParams 문서](https://nextjs.org/docs/app/api-reference/functions/generate-static-params)를 기준으로 구현했다.

[Vercel Portfolio Starter Kit](https://vercel.com/templates/next.js/portfolio-starter-kit)도 파일 기반 글 관리, SEO, 이후 확장 범위를 비교하는 참고 자료로 살펴봤다. 다만 스타터를 복사하지는 않았고, 글 메타데이터 계약과 목록 디자인, 이전·다음 글 탐색은 이 사이트의 규모와 흐름에 맞게 별도로 구성했다.
