# ADR 002: own_site 도구 통합 방식

## 1. 배경

기존 `own_site` 저장소에는 글자수 세기, D-Day 계산기, Base64 변환기, 비밀번호 생성기, 로또 번호 생성기, JSON 포맷터, 단위 변환기 등 여러 브라우저 기반 도구가 HTML/CSS/JavaScript로 구현되어 있다.

Personal Portal은 단순 소개 페이지가 아니라 실제로 사용할 수 있는 포트폴리오 포털을 목표로 하므로, 기존 도구를 현재 Next.js App Router 구조 안으로 흡수해야 한다.

## 2. 대안

1. **기존 HTML 파일을 그대로 public에 복사**
   - 빠르게 연결할 수 있지만, 공통 레이아웃, 테마, 메타데이터, 컴포넌트 재사용성을 얻기 어렵다.
2. **도구마다 개별 라우트를 즉시 생성**
   - SEO에는 유리하지만 초기 마이그레이션 범위가 커지고 UI 일관성을 맞추는 비용이 증가한다.
3. **우선 `/tools` 허브 안에 주요 도구를 React 클라이언트 컴포넌트로 통합**
   - 기존 로직을 유지하면서 현재 포털의 디자인 시스템과 상태 관리 방식으로 점진 이전할 수 있다.

## 3. 결정

초기 통합은 `/tools` 페이지 안의 `ToolStudio` 클라이언트 컴포넌트로 구현한다.

- 글자수 세기, D-Day 계산, Base64 변환, 비밀번호 생성, 로또 번호 생성은 즉시 사용 가능한 React 도구로 이식한다.
- JSON 포맷터, 단위 변환기, QR코드 생성기, 색상 변환기, 만 나이 계산기는 다음 마이그레이션 대상으로 노출한다.
- 브라우저 API가 필요한 기능은 `use client` 경계 안에 둔다.
- 서버 전송이 필요 없는 계산은 클라이언트에서만 처리해 개인정보와 응답 속도를 지킨다.

## 4. 결과

- 포트폴리오 메인에서 “직접 만든 실사용 도구가 있는 지원자”라는 인상을 줄 수 있다.
- 기존 바닐라 JS 프로젝트를 버리지 않고 Next.js 포트폴리오의 핵심 콘텐츠로 재활용한다.
- 향후 도구별 SEO 페이지가 필요해지면 `ToolStudio`의 각 도구를 개별 라우트로 분리할 수 있다.
