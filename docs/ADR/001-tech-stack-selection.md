# ADR 001: 초기 기술 스택 및 아키텍처 선정 (Tech Stack Selection)

## 1. 배경 (Context)
본 프로젝트는 단순한 마크다운 블로그를 넘어, 이력서, 기술 블로그, 유틸리티 도구를 통합하는 포트폴리오 성격의 개인 포털 사이트입니다. 
따라서 검색 엔진 최적화(SEO), 컴포넌트 재사용성, 유지보수의 편의성, 그리고 실무(프로덕션) 수준의 아키텍처 구성이 필수적입니다.

## 2. 대안 (Alternatives)
1. **바닐라 JS + HTML/CSS**: 초보자 학습용으로는 좋으나, 복잡한 유틸리티 도구를 통합하고 라우팅을 관리하기에는 생산성과 유지보수성이 현저히 떨어짐.
2. **React (CRA/Vite) + SPA**: 클라이언트 사이드 렌더링(CSR) 방식으로 인해 초기 로딩 속도와 SEO 측면에서 치명적인 약점이 있음. 블로그의 특성상 구글 검색 노출이 중요함.
3. **Next.js (App Router)**: 서버 사이드 렌더링(SSR)과 정적 사이트 생성(SSG)을 혼합하여 사용할 수 있으며, 현재 프론트엔드 실무 시장의 강력한 표준임.

## 3. 결정 (Decision)
- **Framework**: **Next.js (App Router)**
- **Language**: **TypeScript** (컴파일 단계의 타입 체크로 런타임 에러 방지 및 유지보수성 향상)
- **Styling**: **Tailwind CSS + shadcn/ui** (빠른 개발 속도 확보 및 토스/리디 등 실무에서 사용하는 모던 UI 패턴 도입)
- **Hosting**: **Vercel** (Next.js와의 완벽한 호환성, 제로 설정 CI/CD 자동화)

## 4. 결과 (Consequences)
- **장점**: 압도적인 개발 생산성, 완벽한 SEO 최적화, 컴포넌트 단위의 유틸리티 도구 마이그레이션이 매우 용이해짐. 채용 담당자에게 모던 프론트엔드 생태계 이해도를 확실히 어필할 수 있음.
- **단점**: App Router, Server/Client Component 분리 등 Next.js 고유의 러닝 커브가 발생함.
- **완화 전략**: 마이그레이션 시 클라이언트 인터랙션이 많은 유틸리티 도구는 `use client` 지시어를 명확히 사용하여 점진적으로 학습하며 구현함.
